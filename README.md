# 盈泰副食贸易管理系统

为副食批发部打造的本地单机版**进销存 + 经营分析系统**：按批次入库、按批次先进先出（FIFO）出库、三档价格自动匹配、赊账与回款管理，并生成周度经营报告。数据全部存储在本机 SQLite 文件中，不需要服务器、不需要联网。本项目为东莞高埗新联综合市场盈泰副食贸易部定制，也适用于经营模式相近的个体批发商户。

## 功能特性

以下能力均可在代码中找到对应实现（`backend/app/routers/`、`backend/app/services/`）。

### 进销存核心

- **批次入库**：入库单明细按"批次号 + 生产日期 + 到期日"登记，每条明细生成一个独立库存批次
- **FIFO 出库**：销售出库按"到期日 → 生产日期"优先消耗最早批次，逐笔记录批次出库追踪（`BatchOutbound`），销售成本按批次加权平均计算，单据删除时回冲库存
- **三档价格**：每件商品维护零售价 / 普通批发价 / 大客户价；开单时按客户类型自动匹配（VIP → 大客户价，食堂/工厂/小店 → 批发价，散户 → 零售价），也支持手工指定价格
- **赊账与额度控制**：支持现结、赊账、部分结账；赊账导致欠款超过客户信用额度时开单被拦截；支持后续收款与一键结清
- **退货与盘点**：客户退货、供应商退货两类退货单，退回库存计入原批次；盘点分"生成底表 → 确认差异"两步，记录盘盈盘亏数量与金额

### 库存与预警

- 批次级库存查询（每个批次的剩余量、成本、到期天数）
- 库存总值汇总与分类占比
- 临期预警：默认 30 天，剩余 15 天以内标记为紧急
- 安全库存低库存预警
- 滞销商品清单（默认 30 天无销量且有库存）与清仓建议、积压分析（单商品库存价值占比过高时提示）、库存健康度评分

### 经营分析

- **经营周报**：一键生成近 7 天销售额 / 利润 / 订单数、热销商品 TOP10、分类利润结构、库存积压与临期风险、客户欠款与消费排行，并附备货 / 清库 / 调价建议
- **行情记录**：记录同行报价、厂家调价、市场涨跌、节日行情等类型，标记上涨 / 持平 / 下跌趋势
- **定价参考**：综合批次成本、近 30 天行情、周转速度、淡旺季（按品类与月份的固定规则）计算"保本底价 / 常规批发价 / 大客户价"三档参考价；只出建议、不自动改价，需人工确认，历史记录可查
- **生意顾问问答**：内置 10 类副食行业经营知识（引流品、利润品、大客户锁客、淡旺季、保质期管理、定价防内卷、客户分层、现金流、礼盒清仓、阶梯锁客），按关键词匹配知识点，并附带当前库存总值、临期批次、客户欠款、近期销量等实时数据生成回答；多会话历史持久化。注意：这是本地规则引擎，未接入任何大模型 API

### 回款与系统

- 欠款客户列表、客户对账单、单笔 / 批量还款、逾期客户筛查
- 数据库一键备份 / 恢复 / 下载，恢复前自动再备份一份当前库
- 系统配置键值表、系统信息统计
- 单据导出：销售单 / 入库单打印数据、客户对账单、库存报表、临期报表（均为 JSON 数据接口）
- 后端自动生成接口文档（Swagger `/docs`、ReDoc `/redoc`）

### 前端

- Vue 3 + Element Plus + ECharts，共 15 个页面：经营看板、商品 / 供应商 / 客户、入库开单、销售开单、库存查询 / 库存分析、退货管理、回款管理、行情记录、AI 定价、经营周报、生意顾问、系统设置
- 经营看板展示库存总值、今日销售额、临期预警数、欠款客户数，以及库存分类占比、销售走势、热销 TOP5 图表

## 快速开始

环境要求：Python 3.8+、Node.js 18+（`start.bat` 启动前会检查）。

### 方式一：一键启动（Windows）

双击运行 `start.bat`，脚本会依次完成：安装后端依赖 → 初始化数据库 → 创建初始数据 → 安装前端依赖（已有 node_modules 则跳过）→ 在两个新窗口分别启动后端与前端。

### 方式二：手动启动

后端：

```bash
cd backend
pip install -r requirements.txt
python -c "from app.database import init_db; init_db()"   # 建表
python -m app.init_data                                   # 预置 7 个商品分类、默认供应商与示例客户
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动后访问 `http://localhost:8000/docs` 查看接口文档，`http://localhost:8000/api/health` 为健康检查。

前端（另开一个终端）：

```bash
cd frontend
npm install
npm run dev
```

说明：

- 数据库文件固定为 `backend/yingtai.db`，首次建表后自动生成
- `python -m app.init_data` 可重复执行，已存在的分类、供应商、客户不会重复创建

## 配置说明

- 本项目**不使用环境变量**，全部配置写死在代码中：
  - 数据库路径：`backend/app/database.py` 的 `DB_PATH`
  - 前端开发端口与 `/api` 代理目标：`frontend/vite.config.js` 的 `server` 配置
  - 数据库备份目录：固定为 `backend/backup/`（`backend/app/routers/system_router.py`）
- CORS 允许任意来源（`allow_origins=["*"]`），见 `backend/app/main.py`

## 已知边界与说明

- **端口配置不一致**：`start.bat` 将后端启动在 8000 端口、提示前端地址为 5173；而 `frontend/vite.config.js` 中开发服务器端口是 8080、`/api` 代理指向 `localhost:8765`；`backend/test_api.py` 又写死请求 `localhost:9000`。一键启动后如果前端页面请求失败，请先把这三处端口改成一致（例如将 vite 代理目标改为后端实际端口）。
- **无登录与权限**：系统没有用户认证，任何人拿到地址即可操作全部数据，仅适合本机或可信局域网使用，不要直接暴露到公网。
- **"AI" 能力均为本地规则计算**：定价参考、生意顾问问答、周报建议都由代码内固定规则和统计生成，未接入任何大模型或外部服务，回答质量取决于内置知识库。
- **导出为 JSON 数据**：导出接口返回结构化 JSON（含打印用单据数据），代码中未实现 PDF / Excel 文件生成。
- **`backend/test_api.py` 是手动冒烟脚本**：需在服务运行后执行，脚本内 BASE 地址的端口与默认配置不一致，需自行修改；仓库没有自动化测试。
- 仓库目前将 `frontend/node_modules/`、`__pycache__/` 与数据库文件 `yingtai.db` 提交进了版本库，且缺少 `.gitignore`。
