# 网络行情同步设计

## 目标

为东莞/广东的食用油、调味品和饮料商品提供两类可追溯的网络行情：

- 官方分类行情，用于判断食用油和调味品等品类的整体趋势。
- 具体 SKU 网价，用于采购和定价时的参考。

系统每天自动同步一次，也允许操作员手动立即同步。网络数据不会自动修改商品售价、人工行情或定价结论。

## 来源与地域

- 使用 AnySearch 查询公开来源，服务端通过 `ANYSEARCH_API_KEY` 认证。
- 查询优先使用东莞/广东地域；没有可靠本地公开数据时，回退全国官方行情。
- 官方来源优先国家发改委价格信息和国家粮食和物资储备局等可公开访问的数据。
- SKU 来源保存结果页面链接、来源名称、摘录和获取时间。零售促销价只作为候选参考，不视为官方价格。

## 数据模型

新增独立的网络行情记录，不复用或覆盖 `MarketPrice`：

- `product_id` 可为空，供官方分类行情使用。
- `region`、`quote_kind`（official 或 retail）、`source_name`、`source_url`、`source_excerpt`。
- `observed_at`、`fetched_at`、`price`、`unit`、`trend` 和匹配置信状态。
- `status` 为 `pending`、`accepted` 或 `dismissed`。
- 同一来源、商品、地域和观测日期的相同记录去重。

`pending` 的网络行情不会被 AI 定价读取。操作员采纳后，系统创建对应的 `MarketPrice` 人工确认记录并将网络记录标为 `accepted`；忽略只更新网络记录状态。

## 同步流程

1. 手动同步按钮和每日定时任务调用同一个同步服务。
2. 同步服务读取有效商品及其分类、名称和规格，构造官方分类和 SKU 查询。
3. 服务保存可解析的候选行情、来源元数据与失败状态；不写入正式行情。
4. 操作员在网络行情视图检查来源和价格，选择采纳或忽略。
5. 采纳操作在一个数据库事务中创建 `MarketPrice` 并更新候选记录状态。

本项目为单机 SQLite 部署。定时同步使用单实例调度，并以数据库记录避免同一时间重复运行。

## 界面与配置

- 行情页保留人工行情视图，并新增网络行情视图。
- 网络行情视图支持地域、来源类型、商品和状态筛选，显示来源链接、时间、价格或趋势、采纳和忽略操作。
- 提供立即同步命令及最近同步结果。
- 设置页显示是否已配置 AnySearch 密钥和自动同步时间，但不向浏览器返回密钥。

## 错误处理

- 未配置密钥、网络超时、查询无结果、价格无法解析或 SKU 匹配不唯一时，记录可读的同步结果。
- 失败不删除历史网络行情，不写入 `MarketPrice`，也不影响采购、销售、退货或定价。
- 来源链接仅用于展示；服务器不接受浏览器提供的任意抓取 URL。

## 测试

- 官方地域查询优先东莞/广东，并在无可靠结果时回退全国。
- SKU 查询使用商品名称与规格，且未匹配时保持待确认。
- 重复同步不会创建重复候选记录。
- 同步失败和未配置密钥不会写入正式行情。
- 采纳候选记录后才创建 `MarketPrice`，并保留来源可追溯性。
- 手动与定时同步调用相同服务，且重复运行受到保护。
